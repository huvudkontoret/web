// KL · TIME TRACKING · [ EXPERIMENT ]

Track time where the work happens.

kl is klockan. A CLI, a terminal UI, a menu bar, apps for phone, tablet and watch, and an MCP server, all reading one append-only log on your own disk.

// COMMANDS

One command per event

Projects are created the first time you name them. Starting a timer stops the one running. Every command takes --json. stdout is data, stderr is notices.

See kl help <subcommand> for detailed help.

$ kl status
Show the running timer and today's total. The default.
$ kl start
Start a timer (a running one is stopped first).
$ kl stop
Stop the running timer.
$ kl add
Log a finished session after the fact.
$ kl report
Summarize tracked time per project and day; a week also shows its status and target.
$ kl log
List recent sessions with their short ids.
$ kl edit
Change a session's project, times or note.
$ kl delete
Delete a session (tombstone in the log).
$ kl projects
Manage projects.
$ kl week
Show, close and reopen ISO weeks, and set the week target.
$ kl tui
Full-screen terminal UI: the line, the ruler and the receipt on one screen.
$ kl mcp
Run an MCP server over stdio, exposing kl as tools for agents.
$ kl remind
Reminders: forgotten timer, empty weekday yesterday.
$ kl sync
Sync the event log with the kl sync server.
$ kl config
Read and change settings in the config file.
$ kl completions
Print a shell completion script (zsh, bash or fish).

// AGENTS

Same guards for agents

kl mcp serves nine kl_* tools over stdio. An agent logs time through the same validation as you do. It cannot log the future.

// LOG

Lines are appended.
Nothing is rewritten.

The truth is a JSONL file. State is derived on every run. Corrections are new events that point at old ones.

Sync is optional. Devices exchange lines through kl.huvudkontoret.dev/sync/v1. The clock runs on the local log alone.
